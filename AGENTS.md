# Project guidance

- spale is a dependency-free Swift / AppKit application for macOS 14+ (Swift 6 tools, Swift 5 language mode, no SwiftUI); prefer native APIs. `DESIGN.md` is the authoritative product and interaction specification, and `prototype/` is only the visual and motion reference. The product boundary in `DESIGN.md` (no Git writes, no editor features beyond the listed ones, no shortcuts beyond the key table) moves only with an explicit owner decision.
- Prototype a new visible feature or interaction change in `prototype/` before the native implementation. The owner chooses from the rendered preview in both appearances, so show the recommended design and the strongest alternative. Main pushes that change `prototype/` publish the [prototype page](https://samzong.github.io/spale/).
- `SpaleCore` holds the logic the checks cover: `Git.swift` owns Git invocation, porcelain status parsing, and repository snapshots; `Folder.swift` owns opening target resolution and bounded directory listings; `Text.swift` owns text encoding and line-ending preservation, line diffs, and the projection that maps edits in a rendered diff back to the source text.
- `Sources/spale` holds the app: `main.swift` splits the CLI (any invocation outside the app bundle, including the `spale` and `code` links) from the app, and the CLI only forwards a validated path through the `spale://open` URL; `App.swift` owns the app delegate, menus, quit flow, and the empty-state window with its one-time opening; `FileTree.swift` owns the lazy native file tree and its refresh; `Workspace.swift` owns one repository or folder window: snapshot refresh, streams, the sidebar, full-file view, navigation, and window restoration; `CodeView.swift` owns file sections, the text view, the gutter, and edit routing into buffers; `FileBuffer.swift` is the `NSDocument` for one file (disk snapshots, edits, undo, save); `Watcher.swift` owns file-system events; `Theme.swift` owns colors, fonts, and shared views.
- Draw Theme colors on layers through `Surface` or a view that redraws on appearance change; never assign a static `cgColor`. Give each sidebar region a single background selection signal.
- Read Git only through `Git.run`, which uses `/usr/bin/git --no-optional-locks`. Never stage, commit, write the index, or take `index.lock`, in code or while testing.
- User data is AppKit-native: window restoration state and the `openingPlayed` preference in the `us.samzong.spale` defaults. Do not add a parallel persistence layer.
- No code comments or doc comments.
- Run `make check` for code changes; extend `Tests/SpaleCoreTests/CoreTests.swift` for uncovered `SpaleCore` behavior. Test data uses neutral fictional content in temporary repositories.
- Verify UI changes in the installed native app, including typing, undo, save, live refresh while another process writes files, window restoration, and both appearances; checks alone do not prove these. Remove the test windows and preferences that testing leaves in the installed app.
- `make app` packages `.local/dist/spale.app` and signs it with the single Apple Development identity. `make install` quits spale (it refuses when documents stay open), replaces `/Applications/spale.app`, and links `spale` and `code` in `/opt/homebrew/bin`; it refuses to replace an app or link that belongs to another installation. Use it only when installation is requested. `make uninstall` removes only spale's own app and links.
- `Info.plist` is the single bundle manifest: `Package.swift` embeds it in the `spale` binary and `make app` copies it into the bundle. `Resources/logo.svg` is the icon source and draws the same shaving geometry as `ShavingView` in `Theme.swift`; change both together and run `make icon` to regenerate the committed `Resources/AppIcon.icns`.
- After changes to `CFBundleDocumentTypes` or UTI declarations, handler verification requires the updated app to be installed. If installation was not requested, ask the owner to authorize installation before verifying handlers. Before querying handlers, make sure that `lsregister -dump` lists exactly one `us.samzong.spale` bundle to avoid selecting old builds. Query which application opens each declared type and its known subtypes.
- Keep scratch files and distribution artifacts under `.local/`.

## Release guidance

- A release requires an explicit owner request. Use the version approved by the owner and the tag format `vX.Y.Z`.
- Fetch `origin/main` and tags with `git fetch origin main --tags`. Make sure that the release target belongs to `origin/main`.
- Before tagging, inspect existing tags and releases for the target SHA. If one exists, report its state before continuing. Never delete, move, or recreate a pushed tag or release.
- Run `make check` before tagging. Push the approved tag with `git push origin vX.Y.Z` only within the authorized release scope.
- `.github/workflows/release.yml` checks and packages pull requests. A `v*` tag push also publishes `spale-vX.Y.Z-macos-arm64.zip` as the Latest release.
- Release builds use `macos-26` and `make app SIGNING_IDENTITY=-` for ad-hoc signing. Local builds use the Apple Development identity described above.
- Before claiming release completion, make sure that the tag workflow succeeded and the release asset exists. Inspect vtool output for SDK 26+ and minos 14.0, and lipo output for `arm64`.
- The cask is `Casks/spale.rb` in `samzong/homebrew-tap`. Its `scan-outdated.yml` workflow scans releases on a schedule and supports manual dispatch.
- A tap update requires separate authorization. Wait until the release asset exists before updating the cask. Use the published asset SHA-256.
- Make sure that the cask version and SHA-256 match the published asset. The scan compares versions and cannot repair a checksum for the same version.
